# ag 完整使用指南

> 适用版本：ag 1.2.0
> 环境：macOS / Linux · zsh（补全需要）· Python 3.11+
> 定位：把所有 AI coding agent 收进一个命令里，随意切换、自由扩展
> 前置阅读：[README](../README.md)（安装、它解决什么问题）

---

## 一、它解决什么问题

手上装了十几个 AI coding agent，各自的启动方式都不一样：

- 有的命令名就是启动指令（`codex`、`gemini`、`goose`）
- 有的靠 `.zshrc` 里的别名（`cc`→`claude`、`oc`→`opencode`、`d`→`dsh-tui`）
- OpenClaw 有 8 个角色会话，每个都得敲一长串 `openclaw tui --session agent:xxx:main`
- Hermes 有 3 套 profile，Pi 系有 `pi` / `omp` 两种

结果是：**记不住、找不着、加减一个就要动 `.zshrc`。**

`ag` 把这些问题收在一处：

| 原来的麻烦 | 现在的做法 |
|---|---|
| 十几套启动方式要分别记 | `ag` 一个命令，选择器里挑 |
| OpenClaw 会话串太长 | `ag ot-design` 就行 |
| 加新 agent 要改 `.zshrc` 再重开 shell | `ag add`，存完立刻生效 |
| 装了但忘了叫什么 | `ag scan` 扫出来 |
| 不知道哪个还能跑 | `ag doctor` 体检 |

> **原有的 shell 别名一个都不用删**，`cc` `oc` `d` 照旧能用。
> `ag` 是加在上面的一层统一入口，不是替换。

## 二、30 秒上手

```bash
ag            # 打开全屏选择器：打字即筛选，↑↓ 移动，回车启动，Esc 退出
ag cc         # 直接启动 Claude Code
ag ot-ceo     # 直接进 OpenClaw 的 ceo 会话
ag 设计        # 中文搜索 → 直接筛到 ot-design
ag cc --resume    # 后面的参数原样透传给 agent 自己
```

接着上次干：

```bash
ag last         # 上次用的哪个 agent、上次那个会话 → 直接续上
ag resume       # 列出所有支持续聊的，挑一个
ag resume cc    # 指定续聊 Claude Code
```

按 **Ctrl-G** 可以在任意命令行提示符下直接召唤选择器，不用先敲 `ag`。

`ag <Tab>` 出全部短名补全。

## 三、命令全表

### 启动

| 命令 | 作用 |
|---|---|
| `ag` | 打开模糊选择器 |
| `ag <id>` | 精确启动，例 `ag cc` / `ag ot-product` |
| `ag <id> [参数...]` | 参数透传，例 `ag cc --resume` / `ag gemini -m pro` |
| `ag <关键词>` | 没精确匹配时，打开预填关键词的选择器 |

### 接着上次干

| 命令 | 作用 |
|---|---|
| `ag last` | 上次用的哪个 agent、上次那个会话 → 直接续上 |
| `ag last --new` | 同上，但开新会话 |
| `ag resume [id]` | 续聊；不带 id 会列出支持续聊的 |
| `ag pin [id...]` | 置顶（不带参数列出当前置顶） |
| `ag unpin <id...>` | 取消置顶 |
| `ag stats` | 使用统计（含 frecency 柱状图） |
| `ag stats --history` | 最近启动的时间线 |

### 管理

| 命令 | 作用 |
|---|---|
| `ag ls` | 列出全部，`●` 能跑 / `○` 缺失，并提示怎么装 |
| `ag ls --all` | 连 `hidden = true` 的一起列 |
| `ag ls --json` | 输出 JSON，方便喂给别的脚本 |
| `ag add` | 向导式添加新 agent |
| `ag rm <id>` | 删除（只删那一块，注释保留，删前自动备份） |
| `ag edit` | 用 `$EDITOR` 打开注册表手改 |
| `ag scan` | 扫描 `PATH`，揪出装了但没登记的 agent |
| `ag doctor` | 体检：每条都解析一遍真实路径 |
| `ag install <id>` | 按登记的 `install` 命令安装 |
| `ag install --missing` | 一键补装所有缺失的 |
| `ag which <id>` | 看实际会执行什么命令、在哪个路径 |
| `ag path` | 打印注册表路径 |
| `ag help` | 帮助 |

## 四、选择器怎么操作

```
  ag Agent Gateway  1/29 · 选一个 agent · 输入即筛选
  ❯ 设
  ────────────────────────────────────────────────────────
  ● ot-design     OpenClaw · design 视觉设计师     视觉设计师
  ────────────────────────────────────────────────────────
  openclaw tui --session agent:design:main  tags: openclaw,team
  ↑↓ 移动 · Enter 启动 · Ctrl-R 续聊 · Ctrl-T 置顶 · Ctrl-O 配置 · ? 帮助 · Esc 退出
```

行首符号的含义：

| 符号 | 意思 |
|---|---|
| `★` | 已置顶（颜色仍表示能不能跑：绿=能跑，红=没装） |
| `●` | 可执行文件找得到 |
| `○` | 没装，底部会给安装命令 |

| 按键 | 作用 |
|---|---|
| 直接打字 | 追加到筛选词（支持中文） |
| `↑` `↓` / `Ctrl-P` `Ctrl-N` | 上下移动 |
| `PgUp` `PgDn` / `Home` `End` | 翻页 / 跳首尾 |
| `Backspace` | 删一个字符 |
| `Ctrl-U` | 清空筛选词 |
| `Enter` | 启动选中项（新会话） |
| `Ctrl-R` | 续聊 —— 接上次的会话 |
| `Ctrl-T` | 置顶 / 取消置顶 |
| `Ctrl-O` | 打开该 agent 的配置目录 |
| `?` | 帮助面板 |
| `Esc` / `Ctrl-C` | 退出，什么都不启动 |

**能搜什么**：短名、显示名、说明、标签、别名，中英文都行。

```
ag 设计        →  ot-design
ag 文案写手     →  ot-dev
ag wrapper     →  omc / omx
ag deepseek    →  d
```

**排序会学习你的习惯。** 空查询时按 *置顶 > 常用程度 > 注册表顺序* 排；
一打字就切回按命中质量排：

> 精确短名 > 短名前缀 > 短名含 > 显示名前缀 > 别名前缀 > 主字段含 >
> 只在说明/标签里命中（沉底）

同档之内，置顶和常用程度仍然起作用。所以打 `ce` 时 `ot-ceo` 会排在
`goose`（因为 `opensource` 标签里含 `ce`）前面。

常用程度 = 用过的次数按 **14 天半衰期** 衰减。今天用 3 次的分数约 3.0，
3 天前用 1 次约 0.86，60 天前用 1 次只剩 0.05 —— 常用来的一直在前面，
偶尔翻出来的会自然沉下去。记录写在 `~/.agents/usage.jsonl`，删掉不影响使用，
只是排序退回注册表顺序。

## 六、续聊：接着上次干

启动器只解决了「开哪个」。真正每天在用的痛点是**「接着上次那个活干」**。

### 怎么用

```bash
ag last              # 上次用的哪个 agent、上次那个会话 → 直接续上
ag last --new        # 同上，但明确开新会话
ag resume            # 列出所有支持续聊的，挑一个
ag resume cc         # 指定续聊 Claude Code
ag resume codex --foo   # 续聊 + 透传参数
```

选择器里选中一项按 **`Ctrl-R`** 也行。

### 设计决定：不自己造会话列表

各家 agent 的会话存储格式完全不同（`~/.claude/projects/<编码路径>/<uuid>.jsonl`、
`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`……），而且**私有、会变**。
自己解析等于给自己挖一个永远填不完的坑。

所以 `ag` 的做法是：**把命令转过去，让各家自己的会话选择器干活。**

| 短名 | 续聊时执行 | 出处 |
|---|---|---|
| `d` | `dsh-tui --resume` | `--resume [id]` 恢复上次（或指定 id 的）会话 |
| `cc` | `claude --resume` | 不带 id 会列出会话让你选 |
| `codex` | `codex resume` | 帮助里明写 "picker by default" |
| `gemini` | `gemini --resume` | `-r/--resume`，可用 `latest` 或序号 |
| `grok` | `grok --resume` | 不带参数=最近一个；也可给 id/title |
| `oc` | `opencode --continue` | `-c, --continue` |
| `h` | `hermes --continue` | `--continue [SESSION_NAME]` |
| `ht` | `hermes --tui --continue` | 保持 TUI 模式 |
| `omp` | `omp --resume` | `-r/--resume`，省略即 picker |
| `pa` | `prime-agent --resume` | 打开 agents 视图 |
| `kimi` | `kimi --session` | `-S/--session`，不带 id 交互式挑 |
| `goose` | `goose session --resume` | `session -r` |
| `omx` | `omx resume` | Resume Codex sessions |
| `mcode` | `mcode --session` | 省略即浏览 Sessions |
| `cw` | `codewhale resume` | Resume a saved session |

**示例注册表 29 条里有 15 条已填好，全部实测过 `--help`，不是猜的。**

没填的按 `Ctrl-R` 会明确提示你去加，而不是默默开个新会话 —— 这点很重要，
不然你会以为接上了，其实开了个空的。

### 给自己的 agent 加

注册表里加一行：

```toml
resume = ["--resume"]              # 选项式，如 claude / grok / gemini
resume = ["resume"]                # 子命令式，如 codex / omx
resume = ["session", "--resume"]   # 更长的，如 goose
```

`ag which <id>` 会把它拼出来的完整命令显示出来，可以先确认再启动：

```
  id    : goose
  命令  : goose
  续聊  : goose session --resume
```

> ⚠️ **注意别重复**：`args` 里已经有的参数，`resume` 里别再写一遍。
> 比如 `ht` 的 `args = ["--tui"]`，`resume` 就只写 `["--continue"]`，
> 否则会拼成 `hermes --tui --tui --continue`。
> 回归测试里有一条专门抓这个。

### 看统计

```bash
ag stats              # 用得多不多，一目了然
ag stats --history    # 最近的启动时间线（↻ 表示那次是续聊）
```

```

  ★ cc         62 次 ·   2 小时前  ▇▇▇▇▇▇▇▇▇▇▇▇ Claude Code
```

## 七、加自己的 agent

### 办法 A：向导（最省事）

```bash
ag add
```

一路回车问下来（短名、显示名、可执行文件、参数、说明、标签、别名、安装命令、启动目录），加完**立刻可用**，不用重开 shell。

### 办法 B：一行命令

```bash
ag add --id myagent --cmd myagent --name "我的 Agent" \
        --desc "干什么的" --tags "自研,内部" --alias ma \
        --install "npm i -g myagent"
```

### 办法 C：直接改注册表（最灵活）

```bash
ag edit          # 或 vim ~/.agents/registry.toml
```

在文件末尾追加一块，**保存即生效**：

```toml
[[agent]]
id = "myagent"                # 必填，唯一短名，就是 `ag myagent` 敲的那个
name = "我的 Agent"            # 显示名
cmd = "myagent"               # 必填，可执行文件名或绝对路径
args = ["--flag", "value"]    # 固定参数，每次启动都带
desc = "一句话说明"            # 选择器里显示
tags = ["自研", "内部"]        # 标签，可被搜索
alias = ["ma", "mine"]        # 额外别名
env = { API_KEY = "sk-xxx" }  # 启动时注入的环境变量
cwd = "~/work"                # 启动目录，支持 ~
install = "npm i -g myagent"  # 安装命令，供 `ag install` 用
hidden = false                # true 则不进选择器，但仍可 `ag <id>` 启动
```

### 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一短名，全局不能重 |
| `cmd` | ✅ | 可执行文件名（走 `PATH`）或绝对路径 |
| `name` | | 显示名，缺省用 `id` |
| `args` | | 固定参数数组，写在 `cmd` 之后 |
| `desc` | | 一句话说明 |
| `tags` | | 标签数组，参与搜索但排序沉底 |
| `alias` | | 额外别名数组，`ag <alias>` 等价于 `ag <id>` |
| `env` | | 内联表，启动时合并进环境变量 |
| `cwd` | | 启动前 `chdir` 到这儿 |
| `install` | | 安装命令，`ag install <id>` 会执行它 |
| `update` | | 升级命令，`ag update` 用；不填就退回用 `install` |
| `resume` | | 续聊参数数组，`ag resume` / `Ctrl-R` 用；不填 = 不支持续聊 |
| `sessions` | | 会话历史目录，`ag search` / `ag handoff` 用 |
| `hidden` | | `true` 则不出现在选择器列表 |

### 删除

```bash
ag rm myagent
```

按 `[[agent]]` 块整块删除，**文件里的注释和分节小标题都会保留**。改动前自动备份到 `~/.agents/backups/`（只留最近 20 份）。

## 八、日常维护与排障

### 体检

```bash
ag doctor
```

逐条解析真实路径，输出类似：

```
● d                /Users/you/.nvm/versions/node/v24.0.0/bin/dsh-tui
● cc               /Users/you/.local/bin/claude
○ foo              未安装  npm i -g foo

29/29 可用。
```

### 发现漏网的

```bash
ag scan
```

扫描 `PATH`，比对一份 40 多个常见 agent 名字的清单，列出**装了但没登记**的。当前扫出 7 个：

```
hermes-agent  cursor-agent  qwen  clawdhub  clawhub  agent-browser  cua-driver
```

想收进来就 `ag add` 一下。

### 看某条到底执行什么

```bash
ag which cc
```

```
  id    : cc
  name  : Claude Code
  命令  : claude
  路径  : /Users/you/.local/bin/claude
```

### 搜历史会话

```bash
ag search <关键词>        # 在所有登记的会话历史里搜
ag search 登录页 --limit=10
```

走 ripgrep，1.8G 历史约 1.8 秒。结果按时间倒序，显示 *哪个 agent · 多久以前 ·
哪个项目 · 会话内容摘要 · 文件路径*。找到之后用 `ag resume <id>` 接着聊。

需要注册表里给对应 agent 登记 `sessions` 目录。示例里填好了 4 个：
`cc`(`~/.claude/projects`)、`codex`(`~/.codex/sessions`)、
`gemini`(`~/.gemini/tmp`)、`j`(`~/.jcode/sessions`)。

> 这几个都是**实际翻过目录、确认里面确实是会话记录**才填的。
> 像 `~/.grok/memtrace`、`~/.codewhale/telemetry` 名字像但不是，没收。

### 交接给另一个 agent

```bash
ag handoff           # 从最近用过的那个 agent 交接
ag handoff cc        # 指定从 Claude Code 交接
ag handoff cc --print   # 直接打出来，不复制到剪贴板
```

读那个 agent 最近一次会话的最后 8 轮，加上工作目录，生成一段交接 prompt
塞进剪贴板。切到目标 agent 粘一下，它就知道上文了。

> 会自动跳过子会话（`subagents/`、`sidechain` 这些）—— 那些是主会话派出去的
> 小任务，交接过来没意义。

### 批量升级

十几个 agent 分散在 npm / curl / brew 三种来源，手动升级得记十几套命令。
`ag` 把它收成两条：

```bash
ag outdated            # 先看谁该升
ag update              # 升级（会先列出将执行的命令，问一次再跑）
ag update cc codex     # 只升指定的
ag update --dry-run    # 只看会执行什么，不真跑
ag update --all        # 全部升，不问
```

`ag outdated` 的实际输出：

```
  版本检查  能查的 8 条 · 查不了版本的 10 条

  需要升级 5 条：
    d       0.1.7-rc.2 → 0.2.0-rc.2  DeepSeek Harness
    codex   0.157.1 → 0.159.2  Codex CLI
    gemini  0.61.0 → 0.62.0  Gemini CLI
    ot      2026.6.11 → 2026.9.7  OpenClaw · main 总编辑
    omc     5.3.0 → 5.5.0  Oh My ClaudeCode

  升级：ag update（或 ag update d codex gemini）

  已是最新 3 条：grok, pi, omx
  查不了版本 10 条（重跑安装脚本即升级）：cc, oc, h, omp, pa, j, kimi, goose, mcode, cw
```

**原理**：升级命令优先取注册表的 `update` 字段，没写就退回 `install` ——
多数 agent 的 install 本身就是幂等的「装最新版」，重跑即升级，所以不用每条都写。

版本检测走现成的工具：`npm outdated -g --json` 一次覆盖所有 npm 系的，
`brew outdated --json=v2` 覆盖 brew 系的。**curl 装的查不了版本**，
只能重跑安装脚本 —— 这类会单独列出来说明白，不会假装知道。

> ⚠️ `ag update` 里有不少是 `curl ... | sh`，属于**直接执行远端脚本**。
> 所以不带参数时会先把命令列出来问一次；非交互环境（脚本里）必须显式加 `--all` 才肯跑。

### 缺失的一键补装

```bash
ag install --missing
```

会按各条登记的 `install` 命令逐个执行（**注意**：里面有的是 `curl ... | sh`，属直接执行远端脚本，跑之前自己心里有数）。

### 用另一份注册表

```bash
export AG_REGISTRY=~/proj/agents.toml
ag ls
```

`ag` 本体、补全、备份都会跟着走。适合给某个项目单独配一套入口。

## 九、和 provider 切换器的分工

很多 agent 生态里还有一个「切换供应商 / 模型 / API Key」的需求，
通常由 cc-switch 这类工具负责。它和 `ag` **不冲突，建议并用**：

|               | 管什么                                | 例子                     |
| ------------- | ---------------------------------- | ---------------------- |
| **cc-switch** 等 provider 切换器 | 同一个 agent 换 **供应商 / 模型 / API Key** | Claude Code 从官方切到中转站 |
| **ag**        | 换 **哪个 agent**，以及怎么启动它             | 从 Claude Code 换到 Codex |

一句话：**`ag` 负责把进程拉起来，拉起来之后走哪家 API 仍然归 provider 切换器管。**

## 十、文件位置

| 路径 | 作用 |
|---|---|
| `~/.local/bin/ag` | 主程序（Python，只用标准库，无第三方依赖） |
| `~/.agents/registry.toml` | **注册表 —— 平时要改的就是这个** |
| `~/.agents/ag.zsh` | zsh 补全 + `Ctrl-G` 快捷键 |
| `~/.agents/registry.example.toml` | 模板副本，`ag add` 时可参考 |
| `~/.agents/backups/` | 注册表自动备份（改注册表前自动存，保留最近 20 份） |
| `~/.agents/usage.jsonl` | **使用记录**（frecency 排序用，一行一条，追加写） |
| `~/.agents/pins.json` | **置顶的短名** |
| `~/.zshrc.bak-ag-<时间戳>` | 安装脚本改动 `.zshrc` 前的备份 |

> 最后两个是**状态**不是**配置**。它们跟注册表同级，所以 `AG_REGISTRY`
> 一换，状态也跟着走（适合给项目配独立的一套）。
> `usage.jsonl` 删掉不影响使用，只是排序退回注册表顺序。

想跑回归测试得用仓库里的那份（`tests/`），安装脚本不会把它下到 `~/.agents/`。

`.zshrc` 末尾加了一段（**只加了这一段，别处没动**）：

```zsh
# >>> ag — Agent Gateway >>>
export PATH="$HOME/.local/bin:$PATH"
[[ -r "$HOME/.agents/ag.zsh" ]] && source "$HOME/.agents/ag.zsh"
# <<< ag — Agent Gateway <<<
```

这段是**幂等**的：重复跑安装脚本，检测到已有标记就跳过，不会重复追加。

不想要 `Ctrl-G` 快捷键，在这个块之前加一行：

```zsh
export AG_NO_KEYBIND=1
```

## 十一、常见问题

**改了注册表要重启 shell 吗？**
不用。`ag` 每次运行都重新读注册表，保存即生效。只有改 `.zshrc` 才需要重开或 `source ~/.zshrc`。

**启动报"找不到可执行文件"？**
那条的 `cmd` 不在 `PATH` 上。两个解决办法：`cmd` 直接写绝对路径，或者把它的 bin 目录加进 `PATH`。先 `ag doctor` 看是哪条断了。

**想同时开好几个 agent 并行干活？**
每个 `ag <id>` 是独立进程，开几个终端窗口各跑各的就行。要多窗格同屏用 tmux：

```bash
tmux new -s work
# 然后 Ctrl-B % 分屏，每个 pane 里 ag <id>
```

**选择器行首是红圈 `○`？**
可执行文件没找到。选中那行，底部会显示安装提示；或直接 `ag install <id>`。

**能登记非 AI agent 的命令吗？**
能，它本质就是个"带参数的启动器"。任何常用命令都能收进来：

```bash
ag add --id k9s --cmd k9s --desc "K8s 面板"
ag add --id gp --cmd git --args "pull --rebase" --desc "拉取变基"
```

**短名和已有命令重名了怎么办？**
`ag` 是独立命令名，不会抢。但注意 `ag ls` 里的 `ls` 是 `ag` 的子命令——如果你登记了一个短名叫 `ls` 的 agent，会**优先走子命令**。换个短名，或在注册表里改名。

**出问题了想回滚？**
注册表备份在 `~/.agents/backups/registry.<时间戳>.toml`，直接覆盖回去：

```bash
cp ~/.agents/backups/registry.20260930-221638.toml ~/.agents/registry.toml
```

## 十二、按场景速选

| 场景 | 推荐入口 |
|---|---|
| 日常主力编码 | `ag cc` |
| 多角色协作（选题→研究→写作→发布） | `ag ot` 及 `ag ot-*` 矩阵 |
| 快速问答 / 长文写作 | `ag h` / `ag ht` |
| 多模型对照 | `ag codex` / `ag gemini` / `ag grok` |
| 轻量终端 Agent | `ag omp` / `ag pi` / `ag oc` |
| Web 界面操作 | `ag dsh-web` / `ag hwu` |
| **接着昨天没干完的** | **`ag last`** |
| 想换个 agent 继续同一个活 | `ag resume <id>` 或选择器里 `Ctrl-R` |
| 换了 agent，想把上文带过去 | `ag handoff <来源id>` 然后粘贴 |
| 记得做过某事但忘了哪个 agent | `ag search <关键词>` |
| 想看看哪个 agent 该升级了 | `ag outdated` |
| 不知道用哪个 | 直接 `ag`，搜关键词 |
